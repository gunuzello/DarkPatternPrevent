## 실행 결과

두 주소 모두 초기 HTML에 상품 상세 링크가 없는 client-rendered SPA였다. 기존 HTML-only 경로만 사용하면 “상품 상세 화면을 찾지 못했습니다”로 끝나는 문제가 재현됐다. 이를 보완해 다음 범용 폴백을 추가했다.

- 같은 출처의 공개 페이지만 허용하는 JavaScript 렌더링 폴백
- 링크가 아니라 버튼으로 상품 카드를 노출하는 쇼핑몰에서도 가격·구매 행동 신호를 확인
- 렌더링된 화면을 동일한 증거 캡처 함수로 저장
- 전용 가격 속성이 없는 화면에서도 보이는 통화·원화 가격 라인을 증거로 보존

## 동적 검사 권한

두 테스트몰 모두 소유 확인 토큰이 아직 설치되지 않아 동적 검사 확인 요청이 409로 거절됐다.

동적 검사를 실행하려면 두 테스트몰 중 하나에 발급된 토큰을 메타 태그, `/.well-known/baromi-site-verification` 파일, 또는 DNS TXT 중 한 방식으로 설치한 뒤 확인 버튼을 다시 눌러야 한다. 토큰 자체는 저장하거나 커밋하지 않는다.

## 범용성 원칙

- 테스트몰의 클래스명, 텍스트, URL 패턴을 제품 코드에 추가하지 않는다.
- 상품 상세 URL 규칙은 구조화 데이터·상품 메타·구매 행동·가격 신호를 함께 사용한다.
- SPA와 전통적인 서버 렌더링 페이지를 모두 수용하되, 찾지 못한 단계는 `BLOCKED`로 명시한다.
- 규칙은 구조화된 옵션·금액·행동 증거를 우선하고, 화면 텍스트는 보조 증거로만 보존한다.
- 공개 정적 검사와 소유 확인된 동적 구매 흐름을 보고서에서 분리한다.
