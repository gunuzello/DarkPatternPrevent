# 바로미 상용화 구현 목표

바로미를 데모가 아닌 상용 수준의 쇼핑몰 다크패턴 자동 진단 서비스로 완성한다.

## 우선순위와 완료 조건

1. **빠르고 정확한 기본 진단**
   - 타임아웃은 안전장치일 뿐 성능 개선의 대체물이 아니다.
   - 정상적인 소형 쇼핑몰은 수분을 기다리지 않도록 단계별 병목을 계측하고 병렬화·후보 축소·상태 변화 감지로 실제 진단 시간을 줄인다.
   - 완료되지 않은 화면을 완료로 표시하지 않으며, 도달·차단·경로 미발견을 구분한다.
2. **전체 가이드라인 범위**
   - 16개 진단 유형을 모두 다룬다.
   - 상품 상세·장바구니·주문서뿐 아니라 상품 목록·검색·로그인·회원가입·구독·자동 갱신·해지·탈퇴·환불·정책·쿠폰·추천·인기·후기 표면을 별도로 탐색한다.
   - 자동 판정, 검토 필요, 미검사 범위를 증거와 함께 구분한다.
3. **무료 기본 보고서 우선 완성**
   - AI 호출 없이 규칙·증거·가격 원장·화면 상태만으로 기본 보고서를 먼저 완성한다.
   - 사용자는 기본 보고서를 즉시 열람·다운로드할 수 있어야 한다.
4. **사용자 선택형 유료 AI 정밀 분석**
   - 기본 보고서가 완성된 뒤에만 사용자가 별도로 요청한다. 기본 진단의 속도나 성공 여부를 AI가 막아서는 안 된다.
   - 규칙과 사전 분류기로 확정하지 못한 후보 및 사용자가 선택한 증거만 최소화해 전달한다.
   - AI 결과는 기존 사실 증거를 덮어쓰지 않고 별도 분석 결과·신뢰도·근거·모델 버전·비용으로 남긴다.
   - 무료 이용자는 AI 호출 없이 기본 엔진 결과만 제공받고, 유료 권한이 확인된 이용자만 AI 정밀 분석을 요청할 수 있다.
5. **바로미에 맞는 분류 모델 고도화**
   - 후보, 운영자 라벨, AI 응답, 확정 라벨, 모델 버전, 비용과 지연시간을 재현 가능한 데이터셋으로 축적한다.
   - 단순 프롬프팅을 최종 상태로 삼지 않는다. 사전 분류기 → 평가 데이터셋 → 파인튜닝 적합성 평가 → 필요 시 별도 DL 분류기 순으로 비용·정확도 기준을 통과한 방법을 채택한다.
   - 모델 교체 전 고정 평가셋에서 16개 유형별 정밀도·재현율·미판정률·비용·지연시간을 비교한다.
6. **기능 전체의 UI 가시성**
   - 현재 디자인은 기능 검증용으로 두되, 구매 단계·별도 탐색 영역·16개 규칙·AI 요청/진행/완료/실패·비용과 미검사 사유를 모두 UI에서 확인할 수 있게 한다.
   - 최종 시각 디자인은 프론트 팀원이 교체할 수 있도록 상태와 데이터 계약을 명확히 분리한다.
7. **운영 준비**
   - Spring을 최종 상태 저장소로 전환하고 PostgreSQL, 보관·삭제 정책, 라벨링 데이터셋, 분류기 평가, AI 비용 계측을 운영 환경에서 검증한다.
   - 실제 승인 테스트몰을 반복 검사하며 안전한 탐색, 증거 수집, 규칙 검증, 장애 복구를 확인한 뒤 GitHub에 반영한다.
