# 바로미 개발 명세

## 목표

쇼핑몰 운영자가 플랫폼과 무관하게 구매 흐름의 다크패턴 위험을 사전에 확인하고, 화면 증거와 개선 안내를 바탕으로 수정 후 재검사할 수 있는 B2B SaaS를 개발한다. 카페24는 검증 대상 중 하나일 뿐이며 제품 코드는 특정 플랫폼 URL·선택자·API에 의존하지 않는다. 탐지 결과는 운영자 검토를 위한 위험 신호다.

## 초기 CLI PoC 범위

| 영역 | 구현 |
|---|---|
| 기술 | Next.js App Router, TypeScript, Playwright Chromium, Prisma, SQLite |
| 입력 | CLI의 `clean` 또는 `risky` 시나리오 |
| 탐색 | 상품 상세 → 장바구니 → 주문서. 구매 단계는 모의 상품 한 개를 사용한다 |
| 결과 | 단계별 URL·가격 내역·옵션·비용·스크린샷, 규칙별 발견 항목과 증거를 JSON으로 저장 |
| 저장 | SQLite의 `Scan`과 `Finding`, 로컬의 PNG 및 JSON |
| 상태 | `RUNNING`, `COMPLETED`, `FAILED`. 발견이 없는 완료 건은 빈 `findings` 배열을 반환한다 |

### 탐지 규칙

| 유형 | 위험 신호 | 정상 대조군 | 개선 방향 |
|---|---|---|---|
| DP-01 특정 옵션 사전선택 | 첫 상품 화면에서 사용자의 조작 전에 표시된 유료 추가 옵션의 체크박스·라디오·셀렉트·스위치가 선택됨 | 선물 포장이 미선택 상태로 표시됨 | 유료 옵션을 기본 해제하고 사용자가 직접 선택하도록 한다 |
| DP-02 순차공개 가격책정 | 양수인 필수 비용 항목이 상품 상세 이후에 처음 표시됨 | 필수 처리비가 첫 상품 화면부터 표시됨 | 최초 가격 표시 단계에서 필수 비용을 함께 고지한다 |
| DP-03 긴급성·희소성 표현 | 마감·카운트다운과 재고·동시접속 등 복수 압박 신호가 함께 노출됨 | 해당 표현이 없거나 한 종류의 일반 프로모션 문구만 존재 | 사실 여부를 단정하지 않고 근거 확인을 위한 검토 신호로 표시한다 |

PoC는 비용 식별자와 필수 여부, 옵션 금액을 데모 DOM 속성에서 우선 읽고, 해당 속성이 없는 일부 한국어 가격 문구도 확인한다. 선택형 포장 비용은 필수 비용 검사 대상에서 제외된다. 긴급성·희소성 규칙은 화면 텍스트에서 복수 신호가 함께 보일 때만 사실 판단이 아닌 검토 후보로 기록한다. 결과 상태는 `SUSPECTED`이며 규칙 버전과 화면별 관측값을 포함한다. 범용 DOM 분류, 가격 조건 해석, 법령 예외 판단은 후속 검증 범위다.

### 안전 범위와 테스트

내장 데모는 로컬의 세 구매 경로와 동일 출처 자산만 탐색한다. 외부 정적 진단은 공개 HTTPS 상품의 초기 HTML을 읽고 장바구니·주문서를 미검사로 표시한다. 외부 동적 진단은 서버 발급 메타 태그로 관리 권한을 확인한 쇼핑몰에만 허용하며, 공개 IP로 검증된 주소에 직접 연결하는 중계를 거친다. 주문 확정은 실행하지 않는다. 실제 쇼핑몰 탐색 성능은 운영자가 승인한 테스트몰에서 별도 검증한다. 환경 설정과 결과 파일은 Git에서 제외한다.

위험 데모에서 두 규칙, 정상 데모에서 발견 0건을 기대한다. Playwright 테스트는 탐색 순서, 증거 PNG와 JSON, 외부 주소 거부도 확인한다.

## 확정 제품 범위

- **공모전 P0** — 쇼핑몰 URL 등록과 검사 동의, 허용 도메인 확인, 진단 실행 및 진행 상태, 결과·증거·개선 안내, 수정 후 재진단. 승인된 여러 구조의 테스트몰에서 두 필수 규칙을 검증한다. 플랫폼별 어댑터는 공통 탐색기가 실패하는 경우에만 별도 모듈로 추가한다.
- **API 및 데이터** — `/api/v1`에 쇼핑몰 등록, 진단 생성·조회·중단, 발견 항목·증거·보고서 조회를 제공한다. 진단 단계와 가격 관측을 저장하고, 부분 완료·미검사 범위·실패를 결과 화면에 표시한다.
- **규칙 운영** — 규칙별 법률 근거와 버전, 적용 기준, 개선 안내를 관리한다. 정량 평가 시 정상·위험 사례에서 정밀도·재현율·F1을 측정한다.
- **P1** — 카페24 OAuth, 운영자와 쇼핑몰 관리, 승인된 테스트 계정, 구매·가입·탈퇴 경로 확장, 진단 이력·변경 감지·정기 검사. PostgreSQL과 작업 큐, 비공개 증거 저장을 도입한다.
- **P2** — 구독 결제, PDF 보고서, 운영 플랫폼 확대.

## v1.0 구현 이력

| 명세 | 현재 구현 |
|---|---|
| SCR-01~05 | 소개 → 예시 URL 또는 실제 쇼핑몰 URL과 동의 → 진행·중단 → 결과 → 발견 항목 상세 및 증거 |
| FR-001~002 | 공개 HTTPS 주소와 내장 데모 상품 URL 등록. 동의 시각 저장, SQLite 대기열, 동시 진단 1건 |
| FR-003~007 | 세 구매 단계 탐색, 가격·옵션 및 화면 좌표 수집, 독립된 두 규칙과 화면 증거 |
| FR-008 | 유형별 법률 조항과 개선 안내. 최신 가이드라인의 개별 예외 검증은 후속 범위 |
| FR-009~011 | 대기·진행·완료·부분 완료·실패·중단, 미검사 단계, 보고서 및 같은 조건의 재진단 |
| API §9 | 쇼핑몰 등록·조회, 진단 요청·상태·중단·발견 목록·보고서, 발견 상세, 세션으로 접근을 제한한 PNG |

합성 사례는 상품 1개의 구매 흐름을 진단한다. 외부 쇼핑몰은 초기 HTML 진단과, 사이트 확인 후 실행하는 동적 구매 흐름을 구분한다. 동적 경로는 구현·격리 테스트됐지만 승인된 실제 테스트몰 성능은 별도 측정 대상이다. 세션 쿠키는 현재 브라우저의 조회 범위를 제한한다. 운영자 인증과 로그인 테스트 계정 연동은 운영 출시 전 검증 항목이다. 로컬 합성 사례 40건의 재현 방법과 측정값은 [P0 탐지 평가](EVALUATION.md)에 기록한다.
