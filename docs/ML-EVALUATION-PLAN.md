# 바로미 탐지 성능·학습 계획

## 원칙

바로미는 학습 모델을 먼저 넣는 제품이 아니다. 관측값을 안정적으로 수집하고, 규칙으로 확정 가능한 판정을 규칙으로 처리한 뒤, 모호한 후보만 분류기나 LLM에 보낸다. 딥러닝은 새로운 시각·구조 유형이 규칙과 경량 분류기로 충분히 처리되지 않을 때만 검토한다.

## 쇼핑몰 데이터셋 분리

- **개발/테스트 세트**: 규칙과 수집기 개발에 사용한다.
- **학습 세트**: 사람이 라벨링한 관측값으로 사전·경량 분류기를 개선한다.
- **검증 세트**: 개발자가 결과를 보지 않고 릴리스 후보를 평가한다.
- 같은 쇼핑몰의 PC·모바일·재실행 흐름은 같은 그룹으로 묶는다. 화면 단위로 무작위 분할하지 않아 누수를 막는다.

검증 세트는 학습·규칙 튜닝에 다시 사용하지 않는다. 쇼핑몰 스킨이 바뀌면 새 그룹으로 기록한다.

## 단계별 판정

1. 결정적 규칙: 체크 상태, 해제 전후 총액, 가격 원장, 화면/API 일치 여부.
2. 사전·정규화: 배송비·포장비·수수료·마케팅·자동연장 문구.
3. 경량 분류기: 상품 옵션과 부가서비스처럼 문맥이 필요한 텍스트.
4. LLM 검토: 규칙과 경량 분류기가 합의하지 못한 후보만, 증거 ID와 함께 호출.
5. DL: 시각적 강조·배치·복합 인터랙션을 추가할 때만 별도 실험.

## 첫 가설

- H1: 화면 금액과 가격 API를 함께 확정할 때 순차공개 가격 오탐률이 감소한다.
- H2: 옵션 해제 전후 총액 차이를 사용하면 유료 사전선택 재현율이 증가한다.
- H3: 목록·배너 가격을 가격 원장 0단계로 포함하면 늦은 비용 공개 판정의 재현율이 증가한다.
- H4: 탐색 반복 일치율이 낮은 쇼핑몰에서는 모델 개선보다 수집기 개선이 전체 성능을 더 크게 높인다.

각 실험은 가설, 데이터셋 버전, 규칙/모델 버전, 호출 비용, 정밀도·재현율·정상 상점 오탐률·탐색 성공률을 함께 기록한다.

## 릴리스 게이트

- 검증 세트는 학습에 사용되지 않았는가
- 위험 사례별 증거 ID가 존재하는가
- 상점 그룹 단위로 지표를 계산했는가
- 탐색 실패와 정상 판정을 분리했는가
- 규칙 변경 전후의 오탐·미탐 차이를 확인했는가
- LLM/DL 호출률과 비용이 예산 안에 있는가
