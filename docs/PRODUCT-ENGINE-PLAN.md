# 바로미 상용 서비스 개발 계획

**바로미는 실제 쇼핑몰 운영자가 위험 요소를 진단하고, 근거를 확인하고, 수정 후 재검사하는 유료 서비스다. 개발은 상용 운영을 전제로 한다. 유료 출시 기준과 요금은 서비스 완성 후 논의한다.**

운영자가 비용을 지불하는 이유는 실제 구매 과정에서 문제가 발생하는 위치와 조건을 확인하고 수정할 수 있기 때문이다. 진단 품질은 실제 쇼핑몰에서의 탐색 성공률, 사람이 확인할 수 있는 근거, 독립 평가에서의 탐지 성능과 건당 비용으로 검증한다.


현재 외부 진단은 상품 한 건의 초기 HTML에 제한된다. 장바구니·주문서 도달률과 실제 상점에서의 탐지 정확도는 측정되지 않았다. 합성 사례 52건은 회귀 테스트로 사용한다. 첫 구현의 진단 범위는 유료 옵션 사전선택과 순차공개 가격책정이다.

## 가이드라인 기반 판정 기준

결과 상태는 **위험 신호**, **신호 미발견**, **검토 필요**, **미검사**다. 신호 미발견은 필요한 증거를 모두 확보해 해당 경로에 기준을 적용했을 때만 부여한다. 관측이 상충하거나 예외가 불명확하면 검토 필요, 필수 단계나 관측이 빠지면 미검사로 기록한다. 공정위 가이드라인과 관련 조문에 근거해 기준표와 라벨 지침의 버전을 기록하고 구현과 검증에 적용한다.

| 유형 | 위험 신호 조건 | 예외 및 제외 | 검토 필요 | 근거 |
|---|---|---|---|---|
| 순차공개 가격책정 | 동일 상품·옵션·수량·통화·구매 조건에서 피할 수 없는 비용이 후속 단계에 나타나고, 첫 가격 화면에서 총액에 포함되거나 적정하게 고지된 증거가 없다. 첫 가격 노출인 목록·검색결과·가격 배너를 원장 0단계에 기록한다. 상품 상세가 최초라면 상세를 0단계로 기록한다. | 사용자가 명시적으로 고른 옵션의 가격 차이와 조건이 드러난 회원 할인가를 구분한다. 총액 산정의 정당한 사유가 있는 경우 첫 화면의 제외 항목과 사유를 함께 확인한다. | 필수 옵션 전부에 추가금이 있어 표시가로 구매할 수 없는 경우, 최소 수량으로 단가와 실구매 총액이 달라지는 경우, 지역별 배송비 고지가 모호하거나 가격·항목 연결 근거가 상충하는 경우. | 전자상거래법 제21조의2 제1항 제1호, 시행규칙 제11조의4, 공정위 가이드라인 순차공개 가격책정 항목 |
| 특정 옵션 사전선택 | 사용자가 선택하기 전에 별도 거래에 대한 청약 의사가 표시되어 있다. 유료 부가옵션은 같은 상품과 조건에서 해당 선택만 해제했을 때 결제 예정 총액이 줄어드는지를 우선 검증한다. 별도 거래 여부와 상태 변화의 원인을 함께 확인한다. | ‘선택해 주세요’ 안내값, 저장 배송지·결제수단, 추가 거래 동의가 없는 무료 사은품은 해당 유료 옵션 규칙에서 제외한다. | 해제 비교가 불가능하거나, 총액 변화가 다른 옵션·배송비·쿠폰에도 의존하거나, 무료처럼 보이지만 별도 약정이 있거나, 사용자 행동과 선택 상태 변화 사이의 원인이 모호한 경우. | 전자상거래법 제21조의2 제1항 제2호, 공정위 가이드라인 특정옵션 사전선택 항목 |

## 학습 계획

1. 승인된 상점의 화면·구매 경로와 사람이 붙인 정답을 데이터셋으로 만든다. 가격 변동, 한국어 표현, 모바일 화면, 플랫폼별 차이를 포함한다. 고객 개인정보와 세션 정보는 증거에서 제외한다.
2. 기존 모델을 API로 호출해 기준 성능을 측정한다. 실패가 화면 누락에서 발생하면 탐색기를 고치고, 문구 의미 해석에서 반복되면 프롬프트와 예시를 개선한다.
3. 같은 유형에서 해석 오류가 지속되고 학습에 사용할 라벨이 충분할 때, 파인튜닝을 지원하는 공급자나 모델을 선택해 추가 학습한다. 기존 모델과 같은 미사용 평가셋에서 비교해 개선 효과와 비용을 확인한다.

## AI 호출 정책과 데이터 계약

프로그램은 증거 수집, 금액 계산, 옵션 상태 비교, 규칙 판정까지 실행한다. AI는 수집한 증거의 의미가 모호하고 해석 결과에 따라 판정이 바뀌는 후보에 사용한다.

| 관측 상황 | 처리 |
|---|---|
| 초기 선택 여부, 사용자 조작, 금액, 동일 항목 여부가 확인됨 | 브라우저 관측과 규칙으로 판정 |
| 관측은 충분하지만 옵션 문구나 비용 조건의 의미가 모호함 | 관련 후보를 묶어 텍스트 모델에 구조화된 JSON 전송 |
| 시각적 배치가 판정에 필요한 후속 유형 | 관련 영역 이미지와 증거 ID를 사용할 수 있도록 별도 평가 |
| 단계 미도달, 요소 수집 실패, 금액 불일치 | 재수집을 시도하고 근거가 부족하면 미검사 또는 검토 필요 표시 |

JSON에는 요소 역할·이름·실제 선택 상태·화면 표시 여부, 사용자 행동 전후 시점, 금액 원문·정규화 금액·통화·수량, 단계별 항목 이름과 연결 근거, 주변 문구, 증거 ID를 담는다. 필수 여부처럼 의미 해석이 필요한 값은 미확정 상태를 허용한다. 각 관측에는 출처를 남기고 페이지 전체 HTML과 세션 정보는 모델 입력에서 제외한다. 스크린샷은 고객이 확인할 증거로 저장하며 이미지 호출에는 필요한 영역만 사용한다.

모델의 응답은 판단 유형, 판단 근거, 증거 ID, 보류 이유를 담는 JSON 스키마로 검증한다. 선택 상태와 가격은 브라우저 관측값을 사용한다. 사이트 문구는 분석 데이터로만 전달하고 모델에 브라우저 제어 권한을 주지 않는다.

초기 목표는 판정 단계에 도달한 진단 중 실제 외부 요청이 한 번이라도 발생한 진단의 비율 10% 이하로 제안한다. 전체 접수 건 기준 비율과 후보별 호출률도 기록한다. 파일럿은 진단당 텍스트 요청 1회를 상한으로 두고 이미지 호출을 비활성화한다. 요청 크기·월 예산에도 한도를 둔다. 동일한 증거와 모델·프롬프트 버전에서 기존 결과를 재사용한다. 예산을 넘거나 후보가 처리되지 않으면 검토 필요로 표시한다. 호출 비율과 함께 미검사율, 보류율, 오탐·미탐, p95 비용을 측정한다.

반복되는 의미 판별은 사람이 라벨링한 사례로 경량 분류기부터 비교한다. 예를 들어 추가 구매, 옵션 가격 차이, 조건부 비용을 분류하는 모델을 로컬에서 실행할 수 있다. 딥러닝이나 파인튜닝은 같은 독립 평가셋에서 정확도·보류율·건당 비용을 개선할 때 채택한다. 수집 실패는 크롤러 개선 과제로 기록한다.

## 수집 신뢰성과 첫 개발 단위

- 실행 조건은 한국 IP, ko-KR, Asia/Seoul, 통화·배송지역·세션 조건을 기록하고 고정한다. PC·모바일과 바로구매·장바구니 경유를 각각 경로로 관리한다. 모바일 주소는 사이트에서 확인하고 화면 크기도 고정한다.
- 스크립트 실행 직후, 관련 응답이 정착한 시점, 각 조작 직후에 선택 상태를 기록한다. 장시간 연결이 남으면 관련 요청 완료와 대상 요소 안정화를 기준으로 제한 시간 안에 관측한다. 상품·옵션 ID를 우선 연결하고, 없으면 정규화한 이름·수량·가격과 출처를 함께 비교한다. 연결이 불명확하면 보류한다.
- 장바구니·주문서에서 브라우저가 이미 받은 승인된 API 응답과 소비자 화면을 동일 상품·조건에서 대조한다. 일치하면 이중 확인, API를 관측할 수 없으면 화면 단독 관측, 불일치하면 확정값 사용을 보류한다. 서버에 존재하는 금액만으로 소비자가 봤다고 판단하지 않는다.
- 실패 사유는 로그인 요구, 접근 차단, 품절, 지원하지 않는 경로, 요소 식별 실패, 제한 시간 초과, 가격 불일치로 기록한다. 같은 조건의 새 세션에서 두 번 실행하고 도달 단계·필수 비용·판정 일치율을 기록한다. 두 번 모두 실패한 비율도 별도 표시한다.
- 첫 개발 단위는 승인된 상점에서 0단계부터 주문서까지 한 경로를 두 번 재현하는 것이다. 같은 상품·옵션 연결, 단계별 금액과 증거 ID, 화면·API 검증 상태, 필수 단계 실패의 보고서 반영까지 확인한다. 정상·위험·보류 예시를 각각 재현하고 확정 판정은 외부 AI 호출 0회인지 확인한다.

다음은 형식 검토용 예시다. 증거 ID는 실제 캡처 및 관측 레코드에 연결되며, 아래 URL과 금액은 예시 값이다.


## 개발 중 독립 평가

독립 표본은 규칙·모델·프롬프트를 만드는 데 사용하지 않은 상점과 스킨에서 수집한다. 개발 중 손본 사례는 회귀 검증에 쓰고, 독립 표본에서는 처음 보는 상점에 같은 판정 기준이 적용되는지 측정한다.

- 기존 20곳·100흐름은 수집기 점검의 출발점으로 둔다. 최종 평가는 유형별 양성·정상·애매·탐색 실패를 사전 층화하고, 상점·스킨이 개발용과 평가용에 겹치지 않게 고정한다. 양성을 늘린 표본의 정밀도는 해당 표본의 구성과 함께 공개하고, 운영과 유사한 별도 표본에서 고객 체감 오탐을 측정한다.
- 라벨 지침은 비교 단위, 기준 버전, 필수 증거, 예외와 보류 사례를 정의한다. 두 명이 모델 출력과 상대 라벨을 보지 않고 독립 판정한다. 합의 전 유형별 Cohen의 카파와 단순 일치율을 보고하고, 불일치는 제3자 조정으로 해결한다. 결론이 나지 않는 사례는 보류로 집계한다.
- 주문서 도달률 85%, 유형별 정밀도 90%·재현율 80%는 초기 점추정 목표다. 정밀도는 위험 판정 중 정답 위험의 비율, 재현율은 정답 위험 중 잡아낸 비율이다. 전체 흐름 기준 재현율에서는 알려진 위험 사례의 탐색 실패와 보류를 미탐으로 포함하고, 도달한 사례의 재현율도 함께 제시한다.
- 표본 계획은 유형별 실제 양성 수와 위험 판정 수, 독립 상점 수, 원하는 신뢰구간 폭으로 산정한다. 첫 목표는 주요 지표의 95% 신뢰구간 반폭 10%p 이내이며, 상점 단위로 층 안에서 복원추출해 신뢰구간을 계산한다. 정상 상점 오탐률은 동일한 검사 분량에서 위험 신호가 하나라도 발생한 정상 상점 수를 검사한 정상 상점 수로 나눈다. 분모·실패·보류·플랫폼별 표본 수를 공개한다.
- 브라우저 실행 시간, 재시도 횟수, 저장량, 사람 검토 시간, 모델 사용량으로 건당 비용과 p95를 계산한다. 평가 지표는 개발 중 성능 개선에 사용한다.

## 고객 결과물과 운영 범위

보고서는 **가이드라인 기준 위험 신호**라는 표현을 사용한다. 맨 위에 검사한 상품·페이지·기기·경로·유형·시점과 미검사 사유를 표시한다. 항목별로 첫 가격과 후속 가격, 옵션의 초기 상태와 해제 전후, 화면 위치, 근거 규칙 버전, 수정 방법을 보여준다. 예를 들어 첫 가격 화면에 필수 처리비를 포함하도록 안내하고, 재검사에서는 같은 조건의 이전 증거와 현재 증거를 연결해 해소·지속·신규·비교 불가를 표시한다.

외부 테스트와 고객 진단은 승인된 상점과 실행 범위에서 진행한다. 승인된 테스트 계정·상품과 고객별 증거 접근 권한을 사용하고 스크린샷의 개인정보를 가린다. 계약에서 보관 기간과 삭제 절차를 정한다. 기준 상점은 승인 범위에서 정기 재검사하며, 스킨 또는 플랫폼 업데이트 후 도달률과 가격 대조가 달라지면 운영자에게 확인을 요청한다.

파일럿 범위 밖에는 결제·주문 확정, 적법성 인증·개별 법률 자문, 접근 제한 우회, 두 유형 밖의 위험 판정, 전체 쇼핑몰 일괄 지원 보장이 포함된다.

## 구현 순서와 완료 조건

1. **증거와 재진단 비교.** 진단을 시작한 보고서를 기준으로 저장하고 고객 권한, 상품 페이지, 검사 단계와 규칙 버전을 대조한다. 비교 가능한 항목은 신규·재발견·이번에 미발견으로 표시한다. 누락 단계나 상품 변경이 있으면 비교 불가를 보여준다. 동일 보고서 재진단과 권한 검사를 웹 테스트로 검증한다.
2. **승인된 구매 흐름의 동적 수집.** 현재의 외부 HTML 경로와 분리된 브라우저 실행에서 요청별 주소 검증, 승인된 도메인, 새 세션, 결제 전 종료를 확인한다. Dapde의 시점별 관찰 방식을 참고해 초기 렌더링, 관련 상태 안정화, 행동 직후의 옵션 변화를 기록한다. 승인된 상점에서 동일한 상품을 주문서까지 두 번 재현한다.
   - 구현됨: 결제·주문 확정 동작 금지, 상품→장바구니→주문서의 단일 명확 동작 탐색, 동일 출처 JSON 가격 응답에서 허용된 숫자 경로만 추출하는 수집기와 격리 테스트.
   - 남음: 요청별 공개 주소 고정 및 승인 도메인 경계를 적용한 외부 브라우저 실행 연결, 승인 테스트몰 반복 검증. 이 조건 전에는 정적 외부 진단을 동적 완료로 표시하지 않는다.
3. **가이드라인 규칙 및 검증.** 최초 가격 노출과 단계별 비용을 비교하고 화면과 관측 API의 일치 여부를 기록한다. 개발에 사용하지 않은 상점과 스킨에서 도달률, 반복 실행 일치율, 오탐·미탐을 측정한다.
4. **의미 분석과 운영.** 규칙과 사전으로 판정하기 어려운 후보를 경량 분류기와 텍스트 모델로 비교한다. 증거 ID와 보류 이유를 보고서에 연결하고 호출률, 실행 시간, 비용을 함께 측정한다.
