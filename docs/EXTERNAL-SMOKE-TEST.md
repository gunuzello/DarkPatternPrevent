# 외부 테스트몰 스모크 테스트

최종 확인일: 2026-11-14

## 최신 실행 상태 (2026-11-14)

제공된 두 Pages 주소를 각각 2회씩 반복 실행했으나, 현재 실행 환경에서 DNS 해석이 되지 않았다(`Could not resolve host`). 따라서 이번 실행은 로그인·구매 흐름 검증 성공으로 집계하지 않고 `FETCH_FAILED`로 기록했다. 두 대상 모두 재현성은 1.0이었지만, 이는 동일한 접속 실패가 반복된 값이다.

실제 흐름 검증은 DNS가 복구되거나 새로 제공된 승인 테스트몰 주소로 다시 수행해야 한다.

## 대상

- VERO LIVING 테스트몰
- MEGA SALE 테스트몰

두 사이트 모두 운영자가 제공한 전용 테스트 계정을 사용했다. 계정 식별자와 비밀번호는 저장소·보고서·로그에 기록하지 않는다.

## 확인 범위

1. 공개 첫 화면 접속
2. 헤더 로그인 버튼 클릭
3. 로그인 모달의 아이디·비밀번호 입력
4. 모달 제출 버튼 클릭
5. 로그인 상태 전환 확인

주문 확정, 결제, 외부 제3자 서비스 호출은 실행하지 않았다.

## 구현상 확인된 대응

- 로그인 모달이 열리기 전에는 헤더의 로그인 컨트롤을 한 번만 연다.
- 모달이 열린 뒤에는 보이는 `form` 제출 버튼을 우선 선택한다.
- OTP·CAPTCHA가 나타나면 우회하지 않고 해당 단계에서 탐색을 중단한다.
- 실제 주문·결제 완료를 성공으로 간주하지 않으며, 주문서 직전까지만 탐색한다.

이 문서는 외부 두 사이트의 로그인 경로에 대한 스모크 테스트 기록이며, 모든 쇼핑몰의 호환성을 보증하는 성능 평가가 아니다. 플랫폼별 평가셋과 반복 실행 결과는 별도 평가 문서에 기록한다.

## 로그인 후 진단 CLI

같은 세 환경변수(`BAROMI_SMOKE_URL`, `BAROMI_SMOKE_USERNAME`, `BAROMI_SMOKE_PASSWORD`)로 `npm run scan:external`을 실행하면 로그인 후 주문서 직전까지 동적 진단을 재현할 수 있다. 임시 상점·진단 레코드는 종료 시 삭제되며 결제 제출은 수행하지 않는다.

`BAROMI_SMOKE_REPEAT=2` 또는 `3`을 지정하면 같은 조건으로 반복 실행하고, 발견 항목·최종 도달 단계·완료 상태의 일치율(`repeatability`)을 출력한다. 이 값은 탐지 정확도가 아니라 수집 실행의 재현성 지표다.

반복 실행은 매번 별도 진단 ID와 암호화된 테스트 자격 증명을 사용한다. 각 결과를 비교한 뒤 임시 증거 디렉터리와 상점·진단 레코드를 삭제하므로 운영 데이터와 섞이지 않는다.
